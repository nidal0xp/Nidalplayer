## 2026-11-01 - [Restrict URL Protocols in Electron Navigation & External Links]
**Vulnerability:** The application was vulnerable to navigating to arbitrary internal/external protocols (e.g., `file://`, `smb://`, `javascript:`) due to missing restrictions on `will-navigate`, `setWindowOpenHandler`, and the `open-external` IPC channel.
**Learning:** By default, Electron permits all forms of navigation and IPC payload passthrough if explicitly unhandled. Allowing unrestricted `shell.openExternal` without prior URL validation can lead to Arbitrary Protocol Execution and DoS. Using `new URL()` ensures consistent hostname/protocol parsing to properly sanitize URIs.
**Prevention:** Always explicitly whitelist acceptable URL protocols (`http:`, `https:`) when invoking `shell.openExternal()` or handling custom navigation events using `try...catch` around `new URL()`. Ensure `will-navigate` permits `file:` and local hosts for internal application routing but blocks everything else.
